In the process of the Stage 5 architectural refactoring, the utilization of AI to analyze the design modularity helped to identify the problem of coupling in relation to the connection between workflow logic and in-memory lists. I embraced the idea of the AI to create an abstract layer of the AppointmentRepository through Python's Protocol, which was compatible with the Dependency Inversion Principle, thus keeping the AppointmentService separated from the storage engines. Nevertheless, the AI suggested adding enterprise architecture patterns, such as the event bus, microservice partitioning, and excessive dependency-injection system. I refused to implement those changes because they brought additional networking complexities for an application designed for a small community clinic. The AI suggested creating the interface for repository with multiple methods; nevertheless, I adjusted it to have only three methods—save, find_by_id, and find_all—which complied with the Interface Segregation Principle.
